# Technical decisions and trade-offs

| 결정 | 선택 이유 | 비용 / 대안 |
|---|---|---|
| PostgreSQL + pgvector 하나 | 트랜잭션, 조인, 벡터 검색을 한 저장소에서 설명·실행 | 대규모 분리 운영은 별도 검토 |
| Typed search API | 자유 SQL 없이 조건·시간·단위를 검증 | 자연어에서 구조화 조건을 파싱하는 기능은 후속 |
| 로컬 다국어 임베딩 | 한국어/영어 합성 기록 지원, API 키 없이 실행 | 첫 모델 다운로드, CPU 메모리/지연 비용 |
| pgvector exact cosine search | 작은 데이터에서 필터와 정확한 top-k 검증 우선 | HNSW보다 확장성 낮음; 규모 측정 후 인덱스 도입 |
| SQL hard filter → vector ranking | 필수 입원/검사 조건을 의미 유사도로 상쇄하지 않음 | 조건이 엄격하면 결과 없음 |
| 입원당 최상위 근거 | 여러 청크가 한 환자로 top-k를 독점하지 않음 | 복수 근거 펼치기는 후속 UI |
| Snapshot 단위 적재 | 적재 성공/실패를 명확히 하고 원본 연결 보존 | 업데이트·삭제는 아직 지원하지 않음 |
| 생성형 요약 제외 | 검증 가능한 retrieval을 1주에 완성 | 자연어 답변과 hallucination 평가는 후속 |
| Swagger 데모 | 검색 동작과 근거 확인에 집중 | 별도 프런트엔드는 이후 |

## 의도적으로 뒤로 미룬 것

Agent, Tool Calling, text-to-SQL, LLM summary, AWS, Terraform, FHIR 전체 모델링, streaming CDC, 메시지 큐, microservice 분리는 MVP에서 구현하지 않았습니다. 로컬 Docker 검색 경로를 먼저 검증한 뒤 실제 필요가 확인되는 기능을 추가합니다.

## 면접에서 설명할 포인트

1. 현장의 여러 화면 조회 문제를 환자·입원·시점별 데이터 결합 문제로 바꿨습니다.
2. 관계형 조건은 SQL에 유지하고 텍스트 의미 검색만 벡터로 분리했습니다.
3. 잘못된 단위, 과거 입원, 미래 데이터가 섞이는 실패 조건을 합성 데이터에 넣었습니다.
4. 반환 결과에 검사 ID와 원문 발췌를 제공해 사용자가 근거를 추적할 수 있게 했습니다.
5. 고정 벡터 기반 정확성 테스트와 실제 임베딩 모델의 relevance 평가를 분리했습니다.
6. 부정/과거력/타인 언급은 임베딩만으로 충분하지 않습니다. 후속 단계에서는 assertion 추출과 별도 평가셋을 추가할 수 있습니다.
